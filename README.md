# 历史星云 · Historical Nebula

通过人物、事件与有来源的关系，探索历史中的行动与影响。当前项目包含“汉末 · 三国 / 赤壁”和“史记 · 楚汉之际”两个独立专题，使用 **TypeScript + Vite + Three.js** 验证 3D 关系探索和阅读流程。《史记》接入范围是公元前 209—202 年的楚汉之际样本，并非《史记》全书数字化。产品设计文档中的全部功能与验收目标尚未完成。

## 本地运行

使用 **Node.js 24.x**，或 **Node.js 22.x 且版本不低于 22.12**，并安装随 Node.js 提供的 npm。以下命令在项目根目录执行。

```bash
# 按 package-lock.json 安装依赖
npm ci

# 启动开发服务器
npm run dev
```

打开终端输出的本地地址，通常为 `http://127.0.0.1:5173`。默认只监听本机；测试同一局域网内的手机时，可执行 `npm run dev -- --host 0.0.0.0`，再从手机访问电脑的局域网地址。

```bash
# TypeScript 类型检查
npm run typecheck

# 运行业务逻辑与数据一致性测试
npm test

# 类型检查并生成生产构建，输出到 dist/
npm run build

# 本地检查生产构建，通常为 http://127.0.0.1:4173
npm run preview
```

页面通过开发服务器或静态 HTTP 服务打开，不直接双击 `index.html`。部署时可将 `dist/` 交给静态站点服务器；当前不需要 API 密钥、数据库或后端服务。

## 当前实现

- **3D 星云**：程序生成星点、半透明云雾、人物与事件节点、光晕、关系线及方向提示；提供旋转、平移、缩放、居中、回正视角和全屏展示。全屏时可继续选中节点、阅读浮动详情；点击“退出全屏”或按 Esc 返回常规布局。
- **关系探索**：区分选中对象、展开关联和切换中心；默认最多 12 个关联对象，展开上限为 50 个实体；支持撤销展开、图谱与列表切换。
- **专题与时间筛选**：从专题入口切换赤壁或楚汉之际，分别使用公元 184—280 年、公元前 209—202 年的时间轴；按年或区间探索，区分军事、政治、亲属、影响关系。切换专题会重新建立该专题的中心与筛选范围，不把两部史书的节点混成同一张关系网。
- **内容阅读**：搜索姓名与别名，支持样本中的常用简繁体称谓；提供人物、事件、行动、关系详情和站内来源卡，外部原文可单独打开。
- **探索记录**：对象收藏、保存和恢复探索视图、最近探索、导览进度保存在当前浏览器；支持删除记录与公开探索链接分享。
- **专题导览**：按问题逐步阅读，可进入自由探索并返回导览。
- **设备适配**：手机优先列表，提供三档画质和氛围动态开关，并尊重系统“减少动态效果”设置。

公开探索链接只携带专题、中心、选中对象或关系、完整详情对象、时间与筛选等公开条件。收藏、导览进度、展开集合、相机位置和来源弹层不会放进分享链接。不同浏览器之间不会自动同步本机记录；清理站点存储会删除这些记录。既有赤壁分享链接与本机保存记录仍按原专题恢复。

## 样本数据与范围

当前本地数据包含两个专题：赤壁专题有 **25 个实体（18 位人物、7 个事件）、50 条关系、11 项来源记录和 3 个导览**；《史记》楚汉专题有 **16 个实体（10 位人物、6 个事件）、28 条关系、7 项来源记录和 2 个导览**。合计 **41 个实体、78 条关系、18 项来源记录和 5 个导览**。内容版本为 `topics-local-draft-2026-09-24`；数据定义位于 `src/domain/data.ts` 与 `src/domain/shiji-data.ts`，浏览探索时不依赖远程内容服务。

样本用于验证产品交互，**尚待独立史料审校，不等同于已经正式发布的历史数据库**。实体、行动和关系保留来源引用；史料记载与编辑解释分别标识，日期未知不按无限延续处理。《史记》来源链接指向维基文库原文转录，如[项羽本纪](https://zh.wikisource.org/wiki/史記/卷007)、[高祖本纪](https://zh.wikisource.org/wiki/史記/卷008)、[陈涉世家](https://zh.wikisource.org/wiki/史記/卷048)；这些链接提供核对入口，不代替正式底本审校。正式发布前仍需逐条核对底本、卷次、段落、历法与具体主张。

当前交付没有后端、账号系统、内容管理后台、跨设备同步或全中国历史数据。星云视觉由 Three.js 实时生成，**没有交付 Blender 工程、烘焙贴图或 GLB 模型资产**；Blender 与网页结合属于后续视觉资产制作方向。

## 浏览器与降级

开发目标为支持现代 JavaScript、原生 `dialog`、本机存储和 WebGL 2 的桌面及移动浏览器。建议在较新的 Chrome、Edge、Firefox、Safari 上验证；跨浏览器、实体手机和性能目标仍需专项测试，当前不宣称已经完成兼容性认证。

3D 初始化或渲染失败时，页面切换为同一探索条件下的列表，保留内容阅读入口。用户也可主动使用列表；手机默认优先列表。画质档位主要调整装饰粒子与渲染分辨率，不减少历史内容。剪贴板不可用时提供可手动复制的链接；本机存储写入失败时显示反馈。

## 目录结构

```text
historicalNebula/
├─ index.html                     # 页面入口
├─ package.json                   # 依赖与开发命令
├─ package-lock.json              # 锁定依赖版本
├─ vite.config.ts                 # 构建配置与 Three.js 分包
├─ tsconfig.json                  # TypeScript 配置
├─ src/
│  ├─ main.ts                     # 页面、导航、弹层与本机记录
│  ├─ style.css                   # 布局、视觉样式与响应式适配
│  ├─ domain/
│  │  ├─ types.ts                 # 实体、关系、场景接口类型
│  │  ├─ topics.ts                # 专题边界、时间轴与公元前纪年格式
│  │  ├─ data.ts                  # 赤壁样本和各专题数据入口
│  │  └─ shiji-data.ts            # 《史记》楚汉之际样本
│  ├─ exploration/
│  │  └─ core.ts                  # 筛选、图谱预算、搜索与分享状态
│  ├─ nebula/
│  │  ├─ layout.ts                # 稳定的三维节点布局
│  │  └─ scene.ts                 # Three.js 场景与交互控制
│  └─ ui/
│     └─ icons.ts                 # 图标及文本转义工具
├─ tests/
│  ├─ core.test.ts                # 时间边界、状态、预算、搜索、分享
│  ├─ data.test.ts                # 实体、行动、关系及来源一致性
│  └─ topics.test.ts              # 专题隔离、公元前时间及旧链接兼容
└─ dist/                          # npm run build 生成，不提交到仓库
```

自动化测试覆盖纯业务逻辑和样本引用一致性；它们不能替代浏览器交互、视觉、无障碍、真实设备性能或历史内容审校。

## 后续工作

1. 按产品与技术方案的验收场景补齐交互边界，持续验证历史返回、阅读位置、导览恢复、键盘操作及移动端体验。
2. 在真实手机与不同浏览器上测量加载时间、帧率、点击反馈和长时间运行内存，完善性能与渲染失败恢复。
3. 对赤壁与楚汉样本进行独立内容审校，再扩充《史记》篇章和专题；需要持续运营时接入内容后台、版本管理、纠错和发布流程。
4. 如需进一步提升场景质感，制作并验证 Blender 云雾贴图或特色 GLB 资产，评估压缩、加载预算及手机表现。
