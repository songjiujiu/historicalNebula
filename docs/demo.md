# 可复现的静态演示

静态演示与 Flask/MySQL 生产站共用同一套页面、目录、导读和阅读器。演示构建把仓库内的正文 JSON 快照一起打包，运行时不需要数据库、私有服务、账户或 API 密钥；本机构建不会下载上游语料。

## 构建与预览

使用 Node.js 24.x 和锁定的 npm 依赖：

```bash
npm ci
npm run build:demo
npx vite preview --mode demo --host 127.0.0.1
```

默认入口是 `http://127.0.0.1:4173/historicalNebula/`。构建输出位于 `dist-demo/`，可以交给任意支持目录索引的静态服务器。网站导航使用查询参数和锚点，例如 `?compare=qin-han` 或 `?library=hanshu&volume=1#p2`，无需服务端路由重写。

`HISTORICAL_DEMO_BASE` 是构建进程环境变量，默认 `/historicalNebula/`，可改成 `/` 或其他以斜线开头和结尾的子路径；预览必须使用同一个值。它不接受远程域名，也不需要写入环境文件。PowerShell 在根路径预览的例子：

```powershell
$env:HISTORICAL_DEMO_BASE = '/'
npm run build:demo
npx vite preview --mode demo --host 127.0.0.1
```

直接运行 `vite build --mode demo` 只生成页面资源；发布可阅读的演示必须使用 `npm run build:demo`，以执行正文校验和打包。

## 与生产站的区别

| 项目 | 默认生产构建 | 静态演示构建 |
| --- | --- | --- |
| 命令 | `npm run build` | `npm run build:demo` |
| 输出 | `dist/` | `dist-demo/` |
| 正文地址 | `<base>api/v1/data/...` | `<base>data/...` |
| 数据来源 | Flask 从 MySQL 活动版本读取 | 随演示发布的固定 JSON 快照 |
| 本地 API 代理 | 保留现有配置 | 禁用 |
| 健康检查 | `/api/v1/health` | 无数据库健康接口；检查页面和静态 JSON |

静态演示不会验证 Flask、MySQL、数据库权限或服务器发布流程。它的内容版本固定到所构建的仓库提交，不会自动跟随生产数据库更新。

## 打包范围与内容边界

`public/site/` 提供网页图片、模型和图标。打包脚本只从 `public/data/` 复制已知阅读接口路径对应的 JSON 和《史记》NOTICE，解析全部 JSON 并检查正文编号及基本结构；源快照、环境文件、部署文件及其他未列入白名单的内容不随包发布。当前语料体积约 322 MiB，按卷与按书加载，首次全文检索可能需要下载较大的书内索引。

演示随包保留项目 LICENSE、第三方声明、更新记录、许可说明、各语料来源说明和资产制作说明；`licenses/` 另保留实际捆绑的 OpenCC.js、OpenCC 字典及 Three.js 所附许可声明。`demo-manifest.json` 列出正文与说明文件的路径、字节数及 SHA-256，可用于核对同一份快照；它不替代来源许可审核，也不覆盖编译后的网页资源。来源文档内标为代码或原始存档的路径仍对应源码仓库，不表示这些原始文件随演示包分发。

**代码许可不覆盖全部史料、转录、图谱或图片模型。** [许可说明](licensing.md) 与 [第三方声明](../THIRD_PARTY_NOTICES.md) 分别记录其来源、已知条件和待核范围；演示保留阅读页的来源、缺录和署名信息。信息尚未核明不等于认定没有发布权，本构建也不为这些材料授予新的许可。后续若替换或省略某一来源，需要同步调整正文、目录和检索索引，避免留下无法使用的阅读入口。

当前完整构建保留已有《新唐书》54 卷、《宋史》69 卷，以及相关目录标签和媒体；这些内容的部分再分发许可尚未核明，本轮构建没有替换或省略它们。具体来源、已确认条件和待核范围见上述许可文件，不能把“成功构建”理解为“已完成全部许可核验”。

仓库内旧图谱数据及其非商业许可继续按来源说明处理；当前演示阅读入口不加载旧星图与故事模块。来源资料和模型草稿不会因为采用静态演示就自动纳入同一个代码许可证。

## GitHub Pages 发布

仓库设置中的 Pages 来源选择 GitHub Actions。`.github/workflows/pages.yml` 目前仅提供手动触发：选择要发布的提交，工作流安装锁定依赖、运行测试、构建演示，再上传 `dist-demo/`。工作流使用仓库名作为 base，并只在部署任务授予 Pages 写入和身份令牌权限。手动触发用于明确选择发布版本，不代表代码、内容或媒体取得了统一许可证。

发布后检查仓库子路径下的首页、正文、全文检索、分享链接刷新，以及图片和 CSS 背景请求。没有数据 API 的纯静态托管也应完整工作。此说明不代表 Pages 已启用或站点已发布；以成功部署记录和实际页面为准。
